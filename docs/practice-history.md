## 修改及原因

1. 将历史规则演示移到 src/offline_rules.py；src/six_step.py 接入真实模型，保留冻结输入与完整本机调用记录。模型生成内容不来自测试中的写死答案。
2. 为最终审查截断提供单步重试工具；重试写入新目录，不改原报告、不删原失败。
3. 加强逐字片段、数字、语义维度、单位和派生计算检查。模型声称 supported 不能覆盖程序发现的绑定错误。
4. 按用户要求新建2公里 V2任务及18来源快照；原1公里任务和原运行保留。两版本任务哈希不同，不可声称同题单因素比较。
5. 使用V2失败记录修复 calculation JSON 与 derivations 的格式兼容，加入房型数量、面积和空间记录身份检查，允许模型明确拆出独立原子主张。未核验候选不等于来源根本无数据。
6. 上一步拆分产生更多候选，但程序新增的16条限制没有容错，造成最新真实失败。现将合法输出与送检额度分开：每组轮流选取，最多16条送检，超额完整保存为 not_checked，禁止冒充已支持事实。

修复5的历史说明见 [V2回归修复](furlong-review-fix.md)；修复6见 [超额处理](atom-overflow-fix.md)。原失败记录不随代码更新改成通过。

## 为什么反复失败

前期修复偏重单个失败，未充分验证生成、核验、写报告之间的衔接。既出现绑定不足却错放，也出现格式差异和复合主张导致错拒。写作阶段还可能扩大核验过的窄结论。63项离线测试只覆盖当前案例，不保证未见模型输出、更不证明研究质量稳定。

目前尚未完成：按缺口价值动态重规划；完整的自动修订与再审闭环；同代码、同任务、同快照的预先规定重复试验；独立专家验收。当前最多三轮提议/检查，是冻结资料阅读实验，不是自主联网补资料。

真实资料缺口仍包括两时点完整圈内库存、完整可比年度成交总体、完整开发批准/开工/完工资料。带缺口的诚实报告可以有价值，但不得改成所有事实已证实。

## 看哪些文件

- 每次的 run.json：流程停止、审查状态、调用与费用。
- trace.jsonl：按时间排列的事件；公开副本保留全部事件，将 read_frozen 全文替换为哈希与长度。
- claims.json：候选、原文绑定、模型判决和实际采纳判决。
- report.md / report-audit.json：当次报告及审查问题；未执行到该步骤时文件不存在。
- [公开导出清单](../evidence/live-runs/export-manifest.json)：原件/导出件哈希、变换说明和仅留本机的文件清单。

完整请求、响应、来源全文快照、原始抓取与密钥留在本机忽略目录。公开副本可审阅失败轨迹，但不是包含完整资料的端到端复现包。离线测试可直接从仓库运行；真实重跑需要已有本机冻结资料及自己的API Key。
